# Contractor Management System

Веб-приложение для управления заявками на выполнение работ, взаимодействия заказчиков и исполнителей, а также контроля процесса выполнения заказов.

## О проекте

**Contractor Management System** — это приложение, предназначенное для организации работы между заказчиками, исполнителями и менеджерами. Система позволяет создавать заявки на выполнение работ, просматривать предложения исполнителей, выбирать подходящего кандидата и отслеживать статус выполнения заказа.

## Основные возможности

### Заказчик (Client Organization)
- Создание заявок на выполнение работ.
- Просмотр собственных заявок и их текущих статусов.
- Просмотр откликов исполнителей на заявки.
- Выбор исполнителя и принятие подходящего предложения.
- Отмена заявки.
- Отметка работы как выполненной.

### Исполнитель (Contractor)
- Просмотр доступных открытых заявок.
- Просмотр своих откликов и их статусов
- Просмотр своих смен по месяцам с подсчетом какой доход будет получен от каждой организации

### Менеджер (Manager)
- Просмотр общего списка заявок.
- Управление справочником рабочих позиций.
- Просмотр статистики по организациям

## Статусы заявок

В системе предусмотрены следующие статусы:

- `OPEN` — заявка открыта и доступна для откликов.
- `AGREED` — исполнитель выбран, условия согласованы.
- `EXPIRED` — срок действия заявки истёк.
- `CANCELLED` — заявка отменена заказчиком.
- `CLOSED` — работа завершена.

## Технологический стек

- **Java 21**
- **Spring Boot 4**
- **Spring MVC** — обработка HTTP-запросов и маршрутизация.
- **Spring Security** — аутентификация и разграничение доступа по ролям.
- **Spring Data JPA** — взаимодействие с базой данных.
- **Thymeleaf** — серверный рендеринг HTML-страниц.
- **Bean Validation** — валидация входных данных.
- **SQL** — хранение данных приложения.
- **Maven** — сборка и управление зависимостями.
- **JUnit 5, Mockito** — тестирование приложения и контроллеров.

## Архитектура

Проект построен с разделением ответственности между основными слоями приложения:

- **Controller** — обработка HTTP-запросов и взаимодействие с представлениями.
- **Service** — бизнес-логика приложения.
- **Repository** — доступ к данным через Spring Data JPA.
- **Entity** — сущности, соответствующие данным предметной области.
- **DTO** — передача данных между слоями приложения.
- **Security** — настройка аутентификации и авторизации.
- **Exception** — централизованная обработка ошибок приложения.
- **Templates** — HTML-страницы, отображаемые с помощью Thymeleaf.

## Основные сущности

- `User` — пользователь системы и его учётные данные.
- `ClientOrg` — организация-заказчик.
- `Contractor` — исполнитель.
- `Position` — рабочая позиция или вид работ.
- `WorkRequest` — заявка на выполнение работ.
- `Bid` — отклик исполнителя на заявку.

## Безопасность

Для ограничения доступа используется Spring Security и ролевая модель:

- `MANAGER`
- `CONTRACTOR`
- `CLIENT_ORG`

Доступ к страницам и операциям ограничивается в зависимости от роли пользователя. Для методов контроллеров используется аннотация `@PreAuthorize`.

## Обработка ошибок

В приложении предусмотрена централизованная обработка исключений с помощью `@ControllerAdvice`. Для отображения ошибок предусмотрены отдельные страницы:

- `errors/page_404.html` — страница не найденного ресурса.
- `errors/page_500.html` — страница внутренней ошибки сервера.

## Тестирование

Для проверки приложения используются:

- **JUnit 5** — написание тестов.
- **Mockito** — изоляция контроллеров от бизнес-логики.
